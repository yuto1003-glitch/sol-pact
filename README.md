# ⚔️ SOL-PACT（ソルパクト）

**Solana Devnet で動く、大学生の課題・勉強サボり防止アプリ。**
課題を宣言し、SOL を賭けて「背水の陣」を敷く。制限時間内に終われば達成証明書を獲得、間に合わなければ賭けた SOL は監視役の仲間に没収されます。

> ⚠️ **Devnet 専用です。** Devnet の SOL に金銭的価値はありません。Mainnet では使わないでください。

---

## 主な機能

| 機能 | 内容 |
|---|---|
| 👛 ウォレット接続 | Phantom / Solflare / Backpack に対応。アドレスと Devnet の SOL 残高を表示し、1 SOL の Airdrop ボタンも付いています。画面上部に **DEVNET** を常に表示し、RPC の genesis hash を照合して Devnet であることを確認します。 |
| 🤖 AI作戦参謀 | 外部 API・API キー不要のオフライン AI です。課題文から種類（暗記・演習・読書・レポート・プレゼン・開発・試験・汎用）、分量（100個、2000字、15問、40ページ、10枚…）、締切の緊急度、難易度を読み取ります。そのうえで **3つのミニステップ・推奨制限時間・推奨デポジット額** を提案し、契約フォームに自動で反映します。 |
| 📜 デポジット契約 | 課題タイトル・SOL 数量・監視役アドレス・制限時間（**30秒 / 1分** はデモ用、**30分 / 24時間** は実用、カスタム指定も可）を入力して契約します。送金の **準備 → 署名 → 送信 → Confirmed → Finalized** をリアルタイムに表示し、Finalized になった時点でカウントダウンを始めます。 |
| ⏱ アリーナ | リング型タイマーとミニステップのチェックリストを表示します。残り時間が少なくなると、オレンジの警告から**赤い画面点滅・タイマーの振動・カウント音**に切り替わります。 |
| 🏆 / 💀 判定 | 時間内に「ミッション完了！」を押すと、紙吹雪・ファンファーレとともに**達成証明書**（達成タイム・称号・Tx 署名）が出ます。時間切れになると **TIME UP!** の敗北演出が出ます。 |
| 📚 履歴 | 日時・課題名・仲間アドレス・SOL・結果（達成 / 没収）・達成タイム・称号を記録します。各行から Solana Explorer（`?cluster=devnet`）へ直接リンクしています。 |

### デポジット方式（2種類）

- **契約金庫方式（既定・推奨）**
  ブラウザ内で使い捨ての「金庫」アドレスを生成し、そこへ送金します。
  - 達成した場合: 金庫からあなたへ**自動で返金**します（オンチェーン Tx）。
  - 時間切れの場合: 金庫から監視役へ**自動で没収送金**します（オンチェーン Tx）。
  - ページを閉じている間に時間切れになっても、次に開いたときに没収を実行します。
- **仲間へ直接送金方式**
  契約開始時に監視役へ直接送金します。達成したときの返金は仲間との約束に任せる、シンプルな方式です。

> 🔐 金庫の秘密鍵はブラウザの `localStorage` に保存されます。学習・デモ用の簡易エスクローなので、スマートコントラクトによるトラストレスなエスクローではありません。本人がブラウザの開発者ツールを使えば金庫の鍵を取り出せます。

## 事前準備

1. [Phantom](https://phantom.app/) などの Solana ウォレットをブラウザにインストールします。
2. Phantom の場合: **設定 → 開発者設定 → テストネットモード を ON** にし、ネットワークで **Solana Devnet** を選びます。
3. Devnet の SOL を用意します。アプリの「🚰 1 SOL Airdrop」ボタンか、[faucet.solana.com](https://faucet.solana.com/) を使ってください（Airdrop は回数制限で失敗することがあります）。
4. 監視役（仲間）のウォレットアドレスを用意します。デモでは、自分の別アカウントのアドレスを使っても構いません。

> ウォレットは `file://` で開いたページに注入されません。**必ずローカルサーバー経由で開いてください。**

## ローカルでの起動方法

### Python

```bash
cd solana_test
python -m http.server 8000
```

ブラウザで <http://localhost:8000> を開きます。

### Node.js

```bash
cd solana_test
npx serve .
```

表示された URL（通常は <http://localhost:3000>）を開きます。

## GitHub Pages での公開手順

1. GitHub で新しいリポジトリ（例: `sol-pact`）を作成します。
2. `index.html` と `README.md` をプッシュします。
   ```bash
   git init
   git add index.html README.md
   git commit -m "SOL-PACT initial commit"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/sol-pact.git
   git push -u origin main
   ```
3. リポジトリの **Settings → Pages** を開きます。
4. **Build and deployment → Source** で `Deploy from a branch` を選び、Branch を `main` / `/(root)` にして **Save** します。
5. 1〜2分で `https://<ユーザー名>.github.io/sol-pact/` に公開されます（HTTPS なのでウォレットもそのまま使えます）。

## デモの流れ（約1分）

1. 「ウォレット接続」を押し、残高が少なければ Airdrop で補充します。
2. AI 欄に「TOEIC単語100個」と入力し、**AIに作戦を相談** を押します。ステップ・時間・金額がフォームに入ります。
3. 監視役アドレスを入力し、制限時間を **30秒** に変えて **🔥 SOLを賭けて契約開始** を押します。
4. ウォレットで署名すると、Finalized まで進んだところでカウントダウンが始まります。
5. 次のどちらかを試します。
   - **ミッション完了！** を押す → 🏆 達成演出、金庫から返金 Tx が出ます。
   - 何もせずに放置する → 残り約10秒で画面が赤く点滅し、💀 TIME UP! と没収 Tx が出ます。
6. 下部の履歴から Solana Explorer（Devnet）で各トランザクションを確認できます。

## 技術メモ

- 単一ファイル構成です（`index.html`）。依存は CDN から読み込む [`@solana/web3.js` 1.98.0](https://www.npmjs.com/package/@solana/web3.js) と Google Fonts だけです。
- **ブラウザでの Buffer 対策**：web3.js の IIFE 版にある `SystemProgram.transfer()` は、送金額の変換でグローバルの `Buffer` を参照するため、ブラウザでは `Buffer is not defined` になります。そこで次の 2 つで対処しています。
  - 送金命令は `transferIx()` で `Uint8Array` と `DataView` を使って組み立て、Buffer に依存しません。生成されるバイト列は公式実装と同一です。
  - 予備として、web3.js が同梱している Buffer クラスを、アプリ本体より前でグローバルに公開しています（`<head>` 内。追加の CDN 依存はありません）。
- **Devnet RPC の自動フォールバック**（設定値は `index.html` の `RPC_ENDPOINTS` / `RPC_CFG`）
  - 次の公開 Devnet RPC を上から順に使います。いずれも genesis hash・CORS・必要なメソッドが使えることを確認済みです。

    | 順 | 名前 | URL |
    |---|---|---|
    | 1 | Solana 公式 | `https://api.devnet.solana.com` |
    | 2 | Triton RPC Pool | `https://devnet.rpcpool.com` |
    | 3 | Tatum Gateway | `https://solana-devnet.gateway.tatum.io` |
    | 4 | OnFinality（レート上限が低い） | `https://solana-devnet.api.onfinality.io/public` |

  - 起動時にすべての RPC の genesis hash（`EtWTRABZaYq6iMfeYKouRu166VU2xqa1wcaWoxPkrZBG`）を照合し、Devnet 以外は使いません。
  - 失敗（接続不可・5xx・429）、タイムアウト（9 秒）、2 回続けての応答遅延（3.5 秒超）を検知すると、その RPC を 30 秒間後回しにして次の RPC に切り替えます。切り替えは通知で知らせます。
  - 画面上部の「🛰 RPC」パネルで、各 RPC の状態・応答時間・直近のエラーを確認できます。API キー付きのカスタム RPC を最優先で追加することもできます（Devnet であることを確認してから保存します）。
- 送金はウォレットの `signTransaction` で署名し、アプリが RPC へ送信します。Tx ID は署名から送信前に確定させ、`getSignatureStatuses` を Confirmed → Finalized までポーリングします。
- **ブロックハッシュ期限切れ・ドロップへの対策**（設定値は `TX_CFG`）
  - 署名の直前に、毎回最新のブロックハッシュ（`getLatestBlockhash('confirmed')`）を取得します。
  - 署名のあと、送信する前にブロックハッシュの残り寿命を確認します。30 ブロック未満なら、最新のブロックハッシュで作り直して再署名します。
  - 送信はプリフライト付きです。いずれかの RPC が受理したら、ほかの RPC にも同じ Tx を流して取り込まれやすくします。全 RPC が `Blockhash not found` を返した場合も作り直します。
  - 期限切れで取り込まれなかったと確定した場合も作り直します。ウォレットでの再署名依頼は 1 回まで、金庫（ブラウザ内の鍵）は自動で最大 3 回までです。
  - 「取り込まれていない」と判断する前に、すべての RPC に問い合わせます。遅れている RPC の見落としで、誤って未着金と判定しないためです。
  - 確定確認の上限は Confirmed が 150 秒、Finalized が 180 秒です。署名を送信済みで確定確認だけが終わらない場合は、カウントダウンを開始して裏で最大 15 分確認を続けます。
- **送金失敗時の理由表示**：トランザクションパネルに、次のどれに当たるかと対処法を表示します。RPC ごとの応答やシミュレーションログも「技術的な詳細」で確認できます。
  - 残高不足
  - レント不足（送金額が小さすぎる）
  - ブロックハッシュ期限切れ
  - RPC 応答なし
  - RPC のレート制限
  - 署名キャンセル
  - オンチェーンでの実行失敗
  - 送金シミュレーション失敗
- 契約・履歴はブラウザの `localStorage` に保存されるため、リロードしても進行中の契約は復元されます。
